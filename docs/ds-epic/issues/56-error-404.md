# 56 — error-404 — 404 / error page

One-line objective: rewrite `src/error.vue` to use `bf-default` chrome plus
`bfEmptyState`, distinguishing 404 from 500 while keeping one `h1` and a
back link.

## Context

Depends on #46 (`bf-default`), #33 (`bfEmptyState`). Descends from the "3×
duplicated not-found block" finding (as-built D.1) at the **page** level —
the component-level fix already shipped as `bfEmptyState` in #33; this
issue is the final consumer, closing the finding end to end. Also touches
`src/error.vue`, which is Nuxt's dedicated error-page convention (outside
`pages/`, always rendered on unhandled errors — not itself a route in
epic §7's list but required by it: "404 via `src/error.vue`"). Provenance:
BF-214; D4.

## Scope

- Rewrite `src/error.vue` (existing file, not `pages/wireframes/**`, safe
  to edit):
  - Wrap content in `bf-default` chrome (`<NuxtLayout name="bf-default">`
    — `error.vue` sits outside the pages tree so the layout must be
    invoked explicitly, it is not picked up via `definePageMeta`).
  - Body: `<bf-empty-state :heading="isNotFound ? 'Page not found' : 'Something went wrong'" back-label="Back to home" back-to="/" />`.
  - `isNotFound = computed(() => props.error.statusCode === 404)` drives
    the heading/message split; anything else (500, etc.) gets the generic
    message. One `h1` total (inside `bfEmptyState`, not duplicated by this
    file).
  - Keep the existing `defineProps<{ error: {...} }>()` contract Nuxt's
    error-page convention requires; keep `clearError()`/status-code
    plumbing functionally equivalent to today's file (statusCode drives
    the `<title>` via `useHead`).
- This closes the as-built D.1 finding's third and last consumer — the
  other two (`[area].vue`'s and `insights/[slug].vue`'s inline not-found
  blocks, and `projects/[slug].vue`'s) are replaced by `bfEmptyState`
  directly inside #48/#50/#52's own templates, not here.

## Out of scope

- No edits under `pages/wireframes/**` or `components/wireframe/**` — fails the epic. (The wireframe area keeps its own inline not-found fallbacks unchanged per D2 — this issue does not touch them.)
- Error logging or reporting.
- A custom offline page.

## Styling

- Tokens: existing semantic tokens, no new colour.
- `bfEmptyState` owns its own `--_bf-empty-state-*` variables; this file
  passes only the props listed above.
