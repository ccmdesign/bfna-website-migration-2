# Issue index — accessibility pass 1: code level

**Pass 1 of 2.** Markup, semantics, data and behaviour. Everything visual is
[`docs/a11y-visual-pass/issues.md`](../a11y-visual-pass/issues.md) (issues 111–118); the rule that
divides them is brief D32 — by visual effect, not by file extension, which is why four rows below
edit CSS and change nothing anyone can see.

Ordered, dependency-aware. **Row order is execution order**; `depends-on` is the `Blocked-by` map.
Brief: [`docs/a11y-epic/BRIEF.md`](./BRIEF.md). Per-issue specs go to `docs/a11y-epic/issues/<NN>-<slug>.md`.
Paths are relative to `bfna-website-nuxt/` unless prefixed with `docs/` or `content/`. `gh#`/`site#`
= existing issue folded in or coordinated with (close it when the row merges). Every issue
additionally passes the gates in brief §3 and adds at least one assertion to `check-routes.ts`
(brief §5); the `verify` column names the issue-specific check on top of that.

Numbering continues from [`docs/site-epic/issues.md`](../site-epic/issues.md), whose last row is 91.
