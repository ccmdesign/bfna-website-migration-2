# Accessibility Audit — Actionable Digest

Source: GGS "Accessibility Audit" (Google Doc `1ASUJAtfhDdnxk1R12z2vSKAKWo28HOQdXbTDcMsPBRw`, dated 2026-01-13, by Lilia LaGesse + Danielle Veira). Full extraction: `accessibility-audit.md` (same folder).

Standard: **WCAG 2.1 AA** (framed as the EAA compliance baseline — relevant because of BFNA's transatlantic audience). Audit covered the **current live site** (bfna.org) on 6 representative templates: homepage, Democracy landing, Transponder magazine page, video page, Mailchimp newsletter form, Updates listing. Microsites explicitly out of scope (recommended for a later pass).

Key framing for us: GGS repeatedly notes issues stem from **reusable patterns**, so they expect fixes at the component/template level — which is exactly what the new build gives us for free if we carry the wireframe patterns into Front 3. "Where it applies" below distinguishes fixes we inherit by rebuilding vs. things that need explicit decisions or content work.

Wireframe column refers to the Front 2 lo-fi wireframes at `/wireframes` (semantic HTML, inclusive-components card pattern: cards as `li` in `ul`, heading-first, stretched links, `alt=""` decorative images, skip-link in nav).

## Top 5 actions (by impact)

1. **Lock the interaction-accessibility baseline into Front 3 component specs now**: visible `:focus-visible` styles as a design token, keyboard-operable nav/disclosure, native `<dialog>` or in-page video (no modal traps), DOM order = reading order. This single bundle covers all six HIGH findings in 3.1 and is cheapest to guarantee before any hi-fi build starts.
2. **Design the Directus schema for accessible content**: required alt-text on meaningful images, long-description field for infographics, download/PDF link fields that render file type automatically. Must land before content migration, or we re-import today's `alt="|"` debt.
3. **Resolve the accent-color contrast problem in the token spec**: orange `#fa8900` and green `#4f8d71` need text-safe variants (GGS offers `#d47a0b` / `#a65c00` for orange) or a no-text usage rule. This is inside the "evolve, no rebrand" lane but needs client sign-off since it visibly shifts brand accents — raise with Irene early.
4. **Decide the forms stack** (in-house vs. Mailchimp embed) with 3.5 as the requirements list: specific errors, non-color error cues, accessible confirmation, no reCAPTCHA if avoidable. Four HIGH findings live or die on this one architecture choice.
5. **Scope PDF + infographic remediation as a separate workstream with BFNA** — it's content, not site code, it survives any rebuild untouched, and it needs its own budget/owner conversation (also covers caption-quality editorial practice).

## Notes vs. decisions already made

- **Programs > Projects taxonomy**: no contradiction — finding #9 (inconsistent labels across similar page types) actively supports the standardization. Ensure all listing templates adopt one naming system.
- **No-rebrand constraint**: mild tension — the audit requires changing two brand accent color values (orange, green) for text use. Adjustment, not rebrand, but visible; needs client awareness.
- **Semantic search / archive policy**: nothing in the audit touches either. Fewer-tab-stops and consistent-listing findings are compatible with archive-driven leaner pages.
- **Wireframe validation**: the audit independently prescribes the exact patterns the Front 2 wireframes already use (native HTML over ARIA, skip link, unique card links). Worth citing back to GGS/Irene as evidence the new build addresses the systemic findings.
